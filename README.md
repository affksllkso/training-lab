# TRAINING LAB

日本語の人間執筆文とAI生成文を取り込み、文体の傾向を推定するモデルを学習・評価するツールです。アプリはWindowsのブラウザーから使えます。学習とデータ保存はPC内で行います。

## ブラウザーで使う

**[TRAINING LABを開く](https://affksllkso.github.io/training-lab/)**。WindowsのターミナルやPythonのインストールは不要です。初回はブラウザー用のPython環境を読み込みます。JSONLの取り込み・学習・評価・モデル保存はブラウザー内で実行します。文章と結果はそのブラウザーに保存されるので、ほかの端末へ移す場合は元のJSONLと書き出したモデルを保管してください。

## Windowsでローカル起動

Gemini／Ollamaでの生成、既存の文体ルールとの比較、コマンドライン推論を使う場合はローカル版を起動します。

Python 3.11以上を用意し、このリポジトリのフォルダーで実行します。追加パッケージのインストールは不要です。

```powershell
py -3 app.py
```

起動後、同じPCのブラウザーで `http://127.0.0.1:4181/` を開きます。WindowsでPythonランチャーを使わない場合は `python app.py` でも起動できます。データとモデル履歴は `data/training.sqlite3` に保存されます。

## 取り込み・学習・出力

1. ChatGPTで作成した `gpt_dataset_*.jsonl` と、利用許諾のある人間執筆文のUTF-8 JSONLを取り込みます。
2. 学習を実行し、テストの件数・F1・人間文の誤検出率・カバー率を確認します。生成モデルやジャンルを指定すれば、別枠の評価に回せます。
3. 「モデルJSONを保存」で、ブラウザー内推論に使える文字n-gramの重みとしきい値を書き出します。実験履歴から前のバージョンも取得できます。

生成したモデルはTRAINING LABだけでも試せます。出力のスコアは0〜1で、学習データへの類似傾向を示します。

```powershell
py -3 predict.py sl-モデル名.json 原稿.txt
```

### JSONLの項目

各行に一つのJSONオブジェクトを置きます。

| 項目 | 内容 |
| --- | --- |
| `id`, `label`, `text` | 一意のID、整数ラベル（人間執筆は0、AI生成は1）、本文（正規化後100〜20,000字） |
| `source`, `genre` | 生成元または具体的な資料のURLやID、ジャンル。ジャンルには `category` も可 |
| `license`, `author_id` | 人間執筆文で必須。許諾条件と、一貫した著者ID |
| `model`, `generated_at` | AI生成文の生成モデルと日時。モデルが不明な場合は `unknown` |
| `topic`, `work_id`, `group_id`, `prompt_id`, `prompt` | 同一テーマ・資料・プロンプトをまとめる項目。分割の根拠として前4項目または著者IDが必要 |
| `split` | 必要に応じて `train`、`validation`、`test` を指定 |

IDと正規化済み本文の重複を除きます。著者・出典・テーマ・プロンプトが共通する文や、本文が近似する文はグループ化し、学習とテストにまたがることを防ぎます。学習には両ラベル各2件以上、検証・テストには各1件以上が必要です。固定テストにする場合は該当グループに `split: "test"` を指定し、結果のテスト識別子を照合してください。

文字2〜4グラムのTF-IDFとロジスティック回帰を使います。しきい値を検証データで決め、テストを評価に使います。文体ルールとの比較には、Node.js 22.13以上を用意し、`analyze(text).score` が0〜100を返す既存の解析モジュールを `app.py --baseline <ファイル>` で指定してください。

## Gemini／OllamaでAI生成文を追加

JSONLの各行に `id`、`genre`、`topic`、`prompt` を用意します。Geminiを使う場合は `GEMINI_API_KEY` を現在の環境変数に設定します。Ollamaを使う場合は、ローカルで対象モデルを利用できる状態にします。

```powershell
py -3 generate.py prompts.jsonl --provider gemini --model <モデルID> --limit 10
py -3 generate.py prompts.jsonl --provider ollama --model <ローカルのモデル名> --limit 10
```

成功した文は1件ずつ保存します。同じ計画で再実行すると保存済みIDを飛ばして再開します。APIが429を返した場合に停止します。Geminiへの送信はプロンプトのみで、保存済みデータはローカルに残ります。課金の有無はGemini側のプロジェクト設定に従います。

## 検証とモデルの扱い

```powershell
py -3 -m unittest -v
```

合成データによる動作確認を行っています。利用者のコーパスでの精度は、固定テストと未知モデル・ジャンルの独立評価で確認してください。モデルに含まれる特徴語は学習データに由来します。学習データやモデルを共有する場合は、元データの許諾条件が適用されます。スコアは執筆者の特定や不正認定には使えません。
